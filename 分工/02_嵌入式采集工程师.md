## 📡 采样方案核心思路

### 为什么要 I2S+DMA？

普通 `analogRead()` 是阻塞式的，采样时间不稳定，会造成波形失真。

**I2S+DMA 的好处**：
- 硬件自动把 ADC 数据搬到内存，不占 CPU
- 采样时间精确稳定，波形不失真
- 采样率可以稳定到 4kHz，满足分析 50Hz 到 7次谐波的要求

### 接线引脚

```
ESP32 引脚对照：
ADC_PIN  = 34   (ADC1_CH6)  ← 电流信号（调理后的）
VREF_PIN = 35   (ADC1_CH7)  ← 电压信号（调理后的）
GND      = GND  ← 与调理电路共地
3V3      = 3V3  ← 给调理电路供电
```

## 📁 固件代码（完整可跑）

```cpp
// esp32_current_sampler.ino
// NILM 电流/电压双通道采样器
// 使用 I2S + DMA，采样率 4000 Hz

#include <driver/i2s.h>
#include <driver/adc.h>
#include <math.h>

// 采样参数
#define SAMPLE_RATE    4000   // 4kHz
#define SAMPLE_PERIOD  (1000000 / SAMPLE_RATE)  // 250µs
#define BUFFER_SIZE    4096   // 每个通道采样点数
#define CH_ADC         6      // ADC1_CH6 → GPIO34

// 双缓冲区（ping-pong buffer）
int16_t buffer1[BUFFER_SIZE];
int16_t buffer2[BUFFER_SIZE];
volatile int active_buffer = 0;
volatile bool buffer_ready = false;

// I2S 配置
i2s_config_t i2s_config = {
  .mode = (i2s_mode_t)(I2S_MODE_MASTER | I2S_MODE_RX | I2S_MODE_ADC_BUILT_IN),
  .sample_rate = SAMPLE_RATE,
  .bits_per_sample = I2S_BITS_PER_SAMPLE_16BIT,
  .channel_format = I2S_CHANNEL_FMT_ONLY_RIGHT,
  .communication_format = I2S_COMM_FORMAT_I2S,
  .intr_alloc_flags = ESP_INTR_FLAG_LEVEL1,
  .dma_buf_count = 8,
  .dma_buf_len = 64,
  .use_apll = false,
  .tx_desc_auto_clear = false
};

void setup() {
  Serial.begin(115200);
  delay(500);  // 等串口稳定

  // 配置 ADC1
  adc1_config_width(ADC_WIDTH_BIT_12);  // 12bit, 0~4095
  adc1_config_channel_atten(ADC1_CHANNEL_6, ADC_ATTEN_DB_11);  // 0~3.3V

  // 启动 I2S ADC 模式
  i2s_driver_install(I2S_NUM_0, &i2s_config, 0, NULL);
  i2s_set_adc_mode(ADC_UNIT_1, ADC1_CHANNEL_6);
  i2s_adc_enable(I2S_NUM_0);

  Serial.println("READY");
}

void loop() {
  // 读取一帧数据
  size_t bytes_read = 0;
  int16_t read_buffer[BUFFER_SIZE];

  esp_err_t err = i2s_read(I2S_NUM_0, read_buffer, BUFFER_SIZE * 2, &bytes_read, portMAX_DELAY);

  if (err == ESP_OK) {
    int16_t num_samples = bytes_read / 2;

    // 发送帧头（同步用）
    Serial.print("FRAME_START:");
    Serial.println(num_samples);

    // 发送数据（每行一个采样值）
    for (int i = 0; i < num_samples; i++) {
      int16_t sample = read_buffer[i];
      // 去 ADC 偏置：12bit ADC 中心在 2048，转成 ±1 范围
      float normalized = (sample - 2048.0) / 2048.0;
      Serial.println(normalized, 4);
    }

    Serial.println("FRAME_END");
  }

  delay(50);  // 每次发送完等 50ms，让 PC 端来得及处理
}
```

## 📌 校准方法（两点校准——导师点名要求的）

### 为什么要校准？

ADC 有 offset 和 gain 误差。两点校准就是：
1. **偏移校准**：拔掉所有负载（空载），记录 ADC 读数 M0（应该接近 2048，但实际会有偏移）
2. **增益校准**：接一个已知电流的负载（如 12V/5W 灯泡 = 0.42A），记录 ADC 读数 M1

```
offset = M0 - 2048
gain = (I_known) / (M1 - M0)  // I_known = 已知电流值
```

然后每个样本都做：`I_actual = (raw - offset) * gain`

### 什么是"两点校准"的学术话术？

> **两点校准法**：通过两个已知测量点的响应关系确定传感器的线性增益与偏移，消除系统误差。第一点为空载零点，第二点为已知负载工作点。

## 🐍 PC 端接收：把串口流存成 CSV

```python
# serial_to_csv.py
# 运行环境：Windows/Linux 都可以
import serial
import csv
import sys

PORT = "COM3"   # Windows 下改成你的串口号
BAUD = 115200

ser = serial.Serial(PORT, BAUD, timeout=1)
outfile = open("current_data.csv", "w", newline="")
writer = csv.writer(outfile)
writer.writerow(["recording_id", "timestamp", "current", "label"])

rec_id = 0
buf = []
capture = False

print("等待 FRAME_START...")

while True:
    line = ser.readline().decode().strip()
    if "FRAME_START" in line:
        num = int(line.split(":")[1])
        buf = []
        capture = True
    elif "FRAME_END" in line:
        # 一帧结束，写文件
        label = input("输入当前设备标签: ").strip()
        for i, val in enumerate(buf):
            writer.writerow([rec_id, i / 4000.0, val, label])
        rec_id += 1
        print(f"已保存 {len(buf)} 点 → rec_id={rec_id}")
        buf = []
        capture = False
    elif capture:
        try:
            buf.append(float(line))
        except:
            pass

outfile.close()
```

## ⚠️ 常见坑（都是踩过的）

| 坑 | 原因 | 解决 |
|----|------|------|
| 串口乱码 | 波特率不匹配 | 检查两边都是 115200 |
| 波形全是 4095 | 信号太高 ADC 饱和 | 检查调理电路，减小增益 |
| 波形不对称 | 偏置没在 2048 中心 | 重新做偏移校准 |
| I2S 报错 | 引脚不是 ADC1 通道 | GPIO34 是 ADC1_CH6 别弄错 |
| WiFi 打开时波形乱 | WiFi 射频干扰 ADC | 固件里不初始化 WiFi（默认就不开） |
| BLE 干扰 | ESP32 默认开了蓝牙栈 | 不要 include WiFi.h/BLE |
